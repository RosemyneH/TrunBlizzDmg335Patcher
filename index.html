TrunBlizzDmg335Patcher

Shortens the combat numbers in a 3.3.5a client. 115232 is drawn as 115.2K, 2400000 as 2.4M. Values under 1000 stay as they are. The cut keeps the first decimal and does not round it up.

World numbers over a unit, the scrolling combat text, and the portrait feedback text are the ones that change. Miss, absorb, and the chat combat log stay written out in full.

Build

make

That produces the tests, the Linux patcher, libTrunBlizzDmg335Patcher.so, and the 32-bit TrunBlizzDmg335Patcher.dll plus TrunBlizzDmg335Patcher.exe.

32-bit Wow.exe 12340

Copy TrunBlizzDmg335Patcher.exe and TrunBlizzDmg335Patcher.dll next to Wow.exe. Run the exe and pass it the client:

TrunBlizzDmg335Patcher.exe Wow.exe

It writes Wow.exe.bak once, then adds an import so the game loads the DLL. The DLL checks the 12340 bytes at PlayerNameCreateText before it hooks anything. Run the patcher again and it leaves an already patched client alone. A client that hashes Wow.exe will see a different file after this.

64-bit WowClient64

The 64-bit client is the unstripped build. Copy libTrunBlizzDmg335Patcher.so next to it and run:

./TrunBlizzDmg335Patcher ./WowClient64

That writes TrunBlizzDmg335.sh in the same folder. Launch the script. The library finds PlayerNameCreateText from the binary's symbol table, so a rebuild still works as long as those symbols are still there.
